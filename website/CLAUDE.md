# The website

Rules for `website/`, `build/Make-Pages.mjs`, `build/Ping-IndexNow.mjs`, `netlify.toml` and
`netlify/edge-functions/`. Most of the site is held by `WebsiteTests`, `SiteShotTests` and
`IconTests`; the rest holds because somebody reads it.

## How it is built and deployed

- **`website/public` is the whole site**: static files, no build step, framework or package manifest
  (a build step is to be argued for, not introduced).
- **A push to `main` is a deploy**: Netlify publishes `website/public` as it sits; `netlify.toml`
  (publish directory plus headers) is the whole configuration. `ci.yml` only regenerates the site to
  prove nothing changed, `site.yml` only pings search engines after a release, and `release.yml` and
  `winget.yml` never touch it.
- **The front page (`index.html`) is hand-written; every other page comes from `Make-Pages.mjs`**, run
  by hand. **CI runs it and `git diff --exit-code` over `website/public`**, sitemap excepted.
- **`/features/`, `/why/`, `/numbers/`, `/faq/`, `/install/` are hand-written HTML bodies with
  hand-written Markdown twins** in `website/content/pages/` (like the front page and `home.md`);
  `Make-Pages.mjs` wraps each in the shared shell (`html: true` in `PAGES`) and stamps `data-stamp`
  elements. A new such page is a `PAGES` entry plus `WebsiteTests.Pages`, the 404 list, `llms.txt`
  and the edge function's routes. The FAQ's structured data lives on `/faq/`.
- **The generator's Markdown vocabulary is the union of what its sources use** (unsupported syntax
  renders with its marker); `WebsiteTests.Strip` learns each new construction. In the CHANGELOG, an
  inline code span straight after `(` breaks the page/twin comparison: reword rather than fight it.

## The front page

- **Short on purpose**: the lede, "We fixed Windows Search", the numbers, one user's words, the
  install. Everything else has a page.
- **The headline figure is derived, never typed**: the slowest median in the README's pasted run,
  rounded up to the next whole millisecond, each bar drawn to that scale.
  `TheSiteQuotesTheReadmesOwnBenchmarkNumbers` recomputes it, the bars, range, worst sample and
  tiles, so a new run is: paste it into the README, then change every figure the test names.
- **One `h1`**; the ticket section is an `h2`; no `twitter:title`. **`<title>` and `og:title` are
  "Findra - Fast, private desktop search for Windows"** (the twin's H1 too); the headline stays the
  joke, with a visually hidden "Findra:" and an `aria-hidden` lockup
  (`TheFrontPageTitleAndHeadingsSayWhatFindraIs`).
- **Capitals live in `styles.css`** (`text-transform: uppercase`); text is typed in sentence case.
- **The version is stamped, not typed** (`data-stamp`, the structured data's `softwareVersion` and
  release-notes link, from `Directory.Build.props` and CHANGELOG). **A release commit runs
  `node build/Make-Pages.mjs`.**
- **Structured data uses real schema.org properties** (no `privacyPolicy`; the repository is its own
  node via `targetProduct`). Never invent `aggregateRating` or `review`.
- **"Code signing policy" appears twice** (footer, and beside "not signed"), per SignPath's terms.

## Shots and numbers

- **`docs/shots` and `website/public/shots` are two copies of the same renders**, regenerated by
  `build/Make-Shots.ps1`; `SiteShotTests` fails on differing bytes or printed commands.
- **Shots go through Netlify's Image CDN; PNGs are untouched**: a `<picture>` offers AVIF and WebP
  at two widths via `/.netlify/images`, PNG as the `<img>` fallback, matching file names.
- **Every number is a `--searchbench` measurement** beside its machine.

## Promises

- **Optional website analytics only**: GA4 and Clarity load from `analytics.js` only after
  explicit opt-in. Ads remain denied and Google signals off. Inputs/forms are masked, and
  withdrawal clears this site's analytics cookies and reloads. The English consent banner
  and privacy preferences appear on every HTML page. The desktop app stays telemetry-free.
  CSP permits the required analytics origins; fonts stay local. `PRIVACY.md` separates the
  app policy from the website policy. Regenerate after editing the shared shell or policy.
- **IndexNow is not the page reaching out.** `Ping-IndexNow.mjs` submits sitemap URLs to Bing and
  Yandex; `site.yml` runs it after a successful release, **waiting until the live page names the new
  version**; otherwise by hand, after the deploy is live. **`--send` is required. The key exists only
  in `website/public/<key>.txt`.**
- **Search Console's verification file lives at the publish root**, unmodified.
- **The site names Windows Search and the README may not** (`Repo.Competitors`). The `h1` is the
  joke; do not correct it or carry it back.
- **Nothing promises a release that does not exist.** winget is the install
  (`Repo.WingetIsInTheCatalogue` is true); **the catalogue trails each release by one manual
  submission**, so surfaces say the releases page has each release first. The Microsoft Store is
  linked from the front page and `/install/`, and a Store copy updates through the Store. README,
  `llms.txt` and `home.md` turn over together. **Couple guards to the fact that moves** (a numbered
  CHANGELOG section, never the winget manifests' placeholder hashes).

## Generated pages

- **`/code-signing/` comes from `docs/code-signing-policy.md`** (`PolicyPageTests`; its "Not yet in
  force" note is coupled to the empty signing step).
- **`PRIVACY.md` is the privacy policy**, emitted to `/privacy/` and copied verbatim to
  `/privacy.md`, compared **in both directions**; the generator drops its H1, and the reading column is not in a
  `.panel`.
- **`/changelog/`'s twin is not verbatim**: `releaseNotes` drops Unreleased, every
  `- Documentation:` bullet and link references.
- **Guides answer questions people type** (`/windows-search-not-finding-files/`,
  `/search-inside-pdfs/`, `/find-photos-by-description/`, `/search-recordings-by-speech/`, from
  `website/content/guides/`), linked in every footer, the 404 map, `llms.txt`, sitemap and edge
  function. First sentence is the answer; **say only what the code does today** (the formats
  `DocText` reads, not `FileKinds`' list; the words in pictures come with Photos). A new guide is a
  `PAGES` entry plus a `Guides` entry in `WebsiteTests`.

## Other files

- **No contact form, phone number or postal address**; a test refuses them.
- **Only real edge functions in `netlify/edge-functions/`** (every file there deploys as one; no
  default export fails the build, silently keeping the old site). Node tests live in `tests/edge/`.
- **`markdown.ts` does Accept negotiation**: `Vary: Accept` on **both** branches, q values compared,
  not matched (browsers send `*/*;q=0.8`).
- **Netlify injects a `netlify.new` comment and `hosting-provider`/`netlify-deploy` meta tags into
  every HTML response**, and no site setting stops it. **The edge function takes them back out**
  (`withoutNetlifyPromotion`, `onError: 'bypass'`), tested on markup Netlify actually served. It was
  once deleted by a "documentation" commit and every page carried the link again the same day:
  **never remove it without checking a live page, and check the live page after deploys.**
- **`llms.txt` says what Findra is NOT**: no API, accounts, server or MCP server. **The 404 page is
  ours and lists every real URL.**

## The mark on the site

`website/public/favicon.svg`, the header's data URI and the share images come from
`build/Make-Icon.mjs` (never hand-edit; `IconTests`). Share card 1200x630 and square 1080x1080, both
opaque; the square is for posting by hand (Instagram reads no Open Graph). The share card sets type
from `Quicksand-Regular.ttf` itself.
