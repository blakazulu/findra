  Sixth question - how far does user theming go?

  Shape A as you picked it, corrected on two counts.

  The total is 2.9 GB, not 4.5. I measured the seven files in
  %LOCALAPPDATA%\Prism\models instead of trusting the doc's declared floors, and
  the floors are conservative by a lot. That's a much easier thing to ask a
  stranger for, and it's the number that belongs in the README and the winget
  manifest.

  The four capabilities aren't peers - there's a dependency graph. Two things in
  the code:

  - e5-base's purpose is "documents and transcripts" - a transcript is embedded
    and searched exactly like a document. So ticking Speech silently pulls the
    same 270 MB that Document meaning uses.
  - Media.cs runs whisper-turbo first for language detection and only re-runs
    Hebrew files through the ivrit fine-tune. Hebrew is a second pass, not an 
    alternative - it can't be chosen on its own.

  So Hebrew becomes a sub-item nested under Speech rather than a fifth row, and
  every size on screen is the marginal cost given what's already ticked. Speech
  reads 550 MB when Document meaning is on and 820 MB when it isn't. A fixed
  number would make the total visibly fail to add up. Both states are on screen
  side by side so you can see the size move.

  ---

  That's every design question answered. Before I write the spec, here's the
  whole thing in one place - say if any of it drifted from what you meant:

  Product. Findra, a standalone Windows desktop search widget. A capsule on the
  desktop that unfolds into the results card; a global hotkey opens the same
  card centred on the monitor under the cursor. Tray icon for quit, settings and
  download status. Ships via winget and via git clone && dotnet publish -c 
  Release.

  Processes. Three. A thin elevated helper registered as a logon scheduled task,
  holding NtfsVolume + NameIndex and nothing else - it answers name queries and
  streams journal events over a local named pipe, with a generation counter
  stamped on every reply so a late answer to an abandoned query can't win. The
  UI at normal integrity owns grammar, ranking, content search, settings and the
  card. The content indexer is a child of the UI, so it runs native decoders
  over untrusted files at normal integrity, and quitting the app stops indexing
  by construction.

  Search. All four subsystems. Names instantly; full-text inside documents free;
  photos and video frames via SigLIP-2; speech via Whisper turbo with the ivrit
  second pass for Hebrew; semantic documents and transcripts via e5.

  Models. Per-capability, consented on a first-run preset screen, downloaded to
  %LOCALAPPDATA%\Findra\models, resumable, with capabilities degrading silently
  when a model is absent and a "this needs X, get it?" affordance in the card.
  Enabling one later re-queues only the files it covers.

  Look. Six palettes - Mond, Brass, Verdigris, Paper, Blueprint, Porcelain - as
  a Palette record of accent, ink, ground and isLight, with everything else
  derived. Users pick a dark one and a light one plus a mode: Follow Windows,
  Always dark, Always light. palettes.json in the config folder takes
  user-authored entries. Quicksand throughout.

  Surfaces. The inherited search card, near-verbatim. A first-run download
  screen, presets over a checklist. A settings window with a section rail: Look,
  Opening it, What it searches, Content, About. Palette and pause also on the
  capsule's right-click, so most people never open settings.

  Verification. The five diagnostic modes from day one - --searchprobe,
  --searchmodels, --searchindex, --searchshot, --searchtest - with --searchshot
  as the way UI gets built headlessly, exactly as I used it today.
